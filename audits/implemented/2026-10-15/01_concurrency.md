# 01 Concurrency and shared mutable state (read-only audit)

Scope: `src/pyutilz`, every module that imports `threading`, `asyncio`, `multiprocessing`, `concurrent.futures`, or holds a module-level cache, plus the two baseline entries in `tests/test_meta/_lock_discipline_baseline.json`. I read the high-risk subset in full (config, resilience, psycopg2_pool, single_flight_cache, disk_cache, safe_pickle, llm/factory, llm/_claude_models, openrouter_provider, parallel, kernel_tuning cache, cached_client, logginglib). The other files in the 68-file hit list were checked by grep and by the surrounding code of each hit, not line by line. No code, tests or formatters were touched, and no test was run.

## Findings

| id | file:line | severity | defect | evidence | suggested fix |
|---|---|---|---|---|---|
| C-01 | `src/pyutilz/system/config.py:100-133` (`_reload`) | P2 | The mtime recorded after a reload is stat'ed after the file is read, so an edit landing in between is recorded as already seen and never reloaded. | Thread reads bytes at line 100 (old content). Editor writes new content and mtime T2. Line 133 `self._mtime = stat()` stores T2. The next `_maybe_reload` (line 155) sees `mt == _mtime` and skips. Config stays stale until the next edit. | Stat first: `mt0 = self._path.stat().st_mtime` before `read_bytes()`, store `mt0` after parsing. A later write then has a newer mtime and triggers a reload. |
| C-02 | `src/pyutilz/database/psycopg2_pool.py:97-111` (`_reset_pool`), called at `:180` from `get_connection` | P1 | Any single thread's transient `OperationalError` closes the whole shared pool, including connections other threads currently hold. | Thread A's `_ensure_connection` fails at attempt 1 of 3, then line 180 runs `_reset_pool()`, which calls `_pool.closeall()`. psycopg2's `AbstractConnectionPool.closeall` closes `_used` connections as well as idle ones (per psycopg2 source, not re-verified at runtime here). Thread B, mid-query on a checked-out connection, gets `InterfaceError`/`OperationalError`. When B later calls `putconn`, the pool is closed (`PoolError`), and `_pool` is now `None`, so the next caller builds a new pool. One DB blip in a multi-threaded service fans out to every in-flight request. | Do not tear down the shared pool from a per-call retry. On failure, discard only the bad connection (`putconn(conn, close=True)` is already done) and recreate the pool only when no connection is checked out, or have the pool replace individual bad connections. Serialise pool replacement under `_pool_lock` with a generation counter so that stale holders do not act on a replaced pool. |
| C-03 | `src/pyutilz/database/psycopg2_pool.py:81-94` (`_ensure_pool`), `:97-103` (`_reset_pool`) | P3 | Lock-free fast path reads `_pool` and `_pool_dsn` as two separate globals that the writers update in two separate steps. | Writer at line 92 sets `_pool`, then line 93 sets `_pool_dsn`. A reader on another thread that passes line 81 in between hits line 82 with `_pool_dsn is None != dsn` and raises the "different DSN" `ValueError`. In `_reset_pool`, the fast path can pass line 81, see `_pool` cleared at line 101-102, and `return _pool` (line 84) returns `None`. | Publish one immutable tuple `(pool, dsn)` in a single assignment and read it once into a local in the fast path. Return the local, never re-read the global. |
| C-04 | `src/pyutilz/system/parallel.py:293-316` (`mem_map_array`), esp. `:313-314` | P2 | Check-then-unlink on a shared filename is not atomic, and unlinking a file that is still memory-mapped fails on Windows. | `if os.path.exists(filename): os.unlink(filename)` at 313-314 is a TOCTOU window. Two threads with the same `file_name` can race, and one `unlink` raises `FileNotFoundError`. On Windows, a second call with the same `file_name` while the first `np.load(mmap_mode=...)` mapping is still alive makes `os.unlink` raise `PermissionError`. The docstring's own CV example reuses names, so this is a normal call pattern, not a misuse. | Write to a unique `tempfile` name per call and `os.replace` it into place, or drop the `exists` check and catch `FileNotFoundError` around `unlink`. Document that a name must not be re-mapped while a previous mapping is alive, or keep one mapping per name in a registry. |
| C-05 | `src/pyutilz/llm/_claude_models.py:188-190` (`_openrouter_claude_spec`) | P3 | Bounded-FIFO eviction is a check-then-act on a shared dict with no lock. | Two threads both see `len >= 256` at line 188. Both run `next(iter(d))`, get the same oldest key, and the second `pop` at line 189 raises `KeyError` (this is outside the `try`, so it propagates into `claude_model_spec`). A concurrent insert can also make `next(iter(...))` raise `RuntimeError: dictionary changed size during iteration`. | Use `d.pop(key, None)` and a `threading.Lock` around the check, insert and evict, or use `collections.OrderedDict` with `popitem(last=False)` under a lock. | RESOLVED: llm/_claude_models.py: eviction and insert under _openrouter_specs_lock, pop(key, None), EAFP read; regression test added. |
| C-06 | `src/pyutilz/llm/openrouter_provider/_catalogue.py:61-62` | P3 | Freshness check and value read are two separate reads of a global that other threads set to `None`. | `_health.py:45` and `_health.py:610` set `_pkg()._MODELS_CATALOGUE = None` (the refresh path, under `_MODELS_LOCK`), but the lock-free fast path at 61 does not take it. Thread A passes `_catalogue_is_fresh()` at 61 (value non-None), thread B sets `None`, and A returns `_pkg()._MODELS_CATALOGUE` at 62, which is now `None`. The caller then calls `.values()` on it. | Read once: `cat = _pkg()._MODELS_CATALOGUE`, check `cat is not None and fresh`, return `cat`. | RESOLVED: llm/openrouter_provider/_catalogue.py `_fetch_models_catalogue` reads the global once and returns that snapshot; regression test added. |
| C-07 | `src/pyutilz/core/disk_cache.py:455-490` (`DiskCache.get`) vs `:518-545` (`put`) | P3 | `get` does not take the per-key lock that `put` holds, so a reader can see a half-written pair and delete a valid new entry. | `put` does `os.replace(tmp, path)` (line 541), then `write_sidecar` (line 543). A `get` that runs between the two sees a payload with no sidecar, or a payload and an old sidecar. Either raises `PickleVerificationError` or `OSError`, and both branches call `_drop_corrupt_entry(path)` (`:478-492`), which unlinks the payload that `put` just wrote. Cost is a cache miss plus an orphan sidecar, not wrong data. | Take `self._get_key_lock(key)` around the read path in `get`, or make the sidecar write precede the payload replace so readers never see a payload without a sidecar. Do not drop an entry on a verification failure without re-reading it under the lock. |
| C-08 | `src/pyutilz/system/config.py:179-180` (`get`), `:263-264` (`data` setter) | P3 | `get()` reads `self._data` without the lock, and the `data` setter stores the caller's dict by reference. | `get` does `self._data.get(section)` at 179 with no lock, while `_reload` (`:130-131`) swaps the reference under the lock. Reading one reference is atomic in CPython, so there is no torn read today. | C-09 | `src/pyutilz/system/resilience.py:222-229` and `:317` (`self.state`) | P3 | The breaker's `state` is a public, mutable `CircuitState` object that callers can read or mutate without the lock, and `reset()` swaps the object out from under any holder. | All writes to `self.state` in the class are under `self._lock` (229 in `__init__`, 317 in `reset`). ## Baseline entries (`tests/test_meta/_lock_discipline_baseline.json`)

**Entry 1: `src/pyutilz/system/config.py:130 TomlLiveConfig.self._data`.** Not a defect as a write. The only assignments to `self._data` are at line 73 (`__init__`, before the object is shared), line 131 (`_reload`, inside `with self._lock:`) and line 264 (the `data` setter, inside the lock). The baseline line number 130 is the `with` line of the locked write, so the entry is off by one and points at a site that is already guarded. The meta-test cannot see that `_reload` is only ever called under the lock, which is the documented FP in the test's own docstring. The real residual lock gaps are the unlocked read in `get()` (C-08) and the reload ordering (C-01). Fix: fix C-01 and C-08, then drop the entry (or re-key it to `__init__`, which is the only unguarded write and is safe).

**Entry 2: `src/pyutilz/system/resilience.py:220 CircuitBreaker.self.state`.** Not a defect as a write, and the baseline line number is stale: line 220 is inside the deprecation-warning block of `__init__`. The real assignments are at 229 (`__init__`, under the lock) and 317 (`reset`, under the lock), and both are guarded. The residual issue is the public, mutable `state` attribute, which is tracked as C-09 (P3). Fix: C-09, then remove the baseline entry.

## Verdict

Three real defects need attention, and C-02 is the most serious. C-02 (P1) is the pool reset in `psycopg2_pool.py` that closes connections held by other threads on one thread's transient failure, which turns a single DB blip into a cross-request outage in a threaded service. C-01 (P2) is a silent, persistent stale-config bug in the hot-reload class, and C-04 (P2) is a Windows-specific failure of `mem_map_array` when a name is reused while its mapping is still alive. The remaining six (P3) are narrow check-then-act races or lock-coverage gaps that either crash only under rare interleavings (C-03, C-05, C-06) or lose cache entries without wrong data (C-07, C-08, C-09). Both baseline entries are stale false positives at the write level (the flagged writes are locked or in `__init__`); their real residuals are C-08/C-01 and C-09. Recommend fixing C-02 and C-01 first, then C-04, then the P3 batch, then removing both baseline entries.

Finding count: P0 = 0, P1 = 1, P2 = 2, P3 = 6. Total 9.
