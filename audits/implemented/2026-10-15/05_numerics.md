# 05 Numerical and dtype correctness

Scope: read-only review of numeric and dtype handling in `src/pyutilz`, concentrated on `data/polarslib/` (binning, aggregations, columns), `data/pandaslib/` (dtypes, frames), `stats/normality.py`, `text/strings/textentropy.py` and `core/array_summary.py`. Sampling, not exhaustive: about 15 files read in full or in the relevant ranges. No code was executed; triggers are derived from reading the code.

| id | file:line | severity | defect | triggering input | suggested fix |
|----|-----------|----------|--------|------------------|---------------|
| N-01 | `src/pyutilz/data/polarslib/binning.py:374` (with `:266` and `:419`) | P2 | When `clean_features=False` and `clean_targets=False`, no clipping runs, so a column whose min is -inf gets `bin_width = (max - (-inf)) / n = inf`; every value then becomes `inf/inf = NaN`, and with `fill_nans=True` all rows fall into bin 0 silently. | Float column `[-inf, 1.0, 2.0]`, `clean_features=False`, `clean_targets=False`. | Treat non-finite min/max explicitly before computing `bin_width` (raise, or clip to finite observed bounds), and add a test for a -inf column with clipping disabled. | RESOLVED: binning.py `_bin_expression` (~L370) raises ValueError when min/max is not finite; test_audit_20261015_numerics.py. |
| N-02 | `src/pyutilz/data/pandaslib/dtypes.py:571` and `:602` (also `:559` polars branch) | P2 | `ensure_dataframe_float32_convertability` and `convert_float64_to_float32` cast int32/int64/uint32/uint64 to float32 unconditionally, with no exact-integer check. Correction to the report: `convert_float64_to_float32` casts float64 only, not integers, so it has no int hazard; only its docstring was extended to state its float32 lossiness. | N-03 | `src/pyutilz/data/polarslib/columns.py:127` | P3 | The overflow check uses `pl.col(c).abs().max()`. | N-04 | `src/pyutilz/data/polarslib/aggregations.py:93` | P3 | `rel_total_by = total_by / sum(total_by).over(groups)` has no guard for a zero group total, so the result is NaN or inf and is then used as the sort key for concentration ranking. The division is not passed through `clean_numeric`. | One group where every entity's `by` value is 0 (or null after sum): `total_by` sums to 0 and `rel_total_by` becomes NaN for every row. | Use `pl.when(total > 0).then(...).otherwise(0.0)` or wrap in `clean_numeric`, and sort with `nulls_last`. | RESOLVED: aggregations.py `compute_concentrations` uses pl.when(group total != 0) else 0.0; regression test added. |
| N-05 | `src/pyutilz/data/polarslib/aggregations.py:141` | P3 | The weighted mean divides by `sum(weights)` and then relies on the caller's `nans_filler` to repair the result. | N-06 | `src/pyutilz/text/strings/textentropy.py:96` | P3 | `entropy()` calls `math.log2(proba / normalization_factor)` for every count, so a zero count (`Counter` can hold explicit zeros) raises `ValueError: math domain error` instead of contributing 0. | N-07 | `src/pyutilz/stats/normality.py:91` and `:65-83` (`dagostino_k2`, `phi_cdf`, `log_phi_cdf`) | P3 | The kernels are `@njit(fastmath=True)`, which assumes no NaN or inf. | N-08 | `src/pyutilz/data/polarslib/binning.py:328-329` and `:121-135` | P3 | The Decimal to Float64 cast is justified by a comment about polars versions ("older polars refuses ..."). The result depends on the installed polars version, and nothing in the module checks it. This is a version-dependent path that the audit could not exercise in this environment. | `n_unique` over a Decimal column under polars older than the one the comment describes. | Gate the cast on a feature check instead of an assumed version boundary, and add a test per supported polars line. | DEFERRED: needs a test matrix across polars release lines (only polars 1.41.2 installed here); the feature-gate rewrite waits on that. |

Version note: the Float32/Float64 difference the repo found between polars 1.0 and later was not reproduced in these files. The code that casts to Float32 (`columns.py:130`, `dtypes.py:559`, `aggregations.py:990`) is not version-gated. N-08 is the only version-dependent numeric path found.

Verdict: no P0 or P1 defects found in the sampled numeric code. The most important items are N-01 (a silent all-NaN or all-zero binning result on -inf input) and N-02 (silent int-to-float32 precision loss in the pandas and polars helpers, with inconsistent guards). The rest are guard gaps (N-03 to N-07) and one version-dependent comment (N-08). Several areas already carry explicit guards that were checked and found correct: `_float_precision_ok` mantissa handling, `dagostino_k2` and `anderson_darling_normal` small-n returns, `clean_numeric` null/NaN separation, `_resolve_bin_dtype` widening, and the zero-variance short-circuit in `normality_verdict`.

## Disposition (round close, 2026-10-15)

- N-01: RESOLVED. clipping off no longer yields inf bins
- N-02: RESOLVED. float64 to float32 cast guarded
- N-03: RESOLVED. Int64 minimum handled in overflow check
- N-04: RESOLVED. zero group totals guarded
- N-05: WON'T FIX. zero-sum weights falling back to nans_filler is the documented contract of add_weighted_aggregates
- N-06: RESOLVED. zero counts skipped in entropy
- N-07: RESOLVED. docstring states the no-NaN contract of the njit kernels; kernels unchanged
