### F01. [High] `mypy src/pyutilz` — a declared-clean BLOCKING gate — aborts with an INTERNAL ERROR and exit code 2, making its findings nondeterministic — pyproject.toml:551
- **Disposition**: OPEN
- **Category**: gate-integrity
- **Problem**: The repo declares this gate clean and blocking in three places: `pyproject.toml:551-561`, `.github/workflows/mypy-full.yml:5-7` ("`mypy src/pyutilz` verified clean (0 errors, 113 source files)", `advisory: false`), and the `mypy-full-blocking` pre-commit hook (`entry: python -m mypy`, `stages: [pre-commit]`). Run verbatim it is neither clean nor deterministic:
  ```
  $ D:/ProgramData/anaconda3/python.exe -m mypy src/pyutilz ; echo EXITCODE=$?
  ...
  D:\ProgramData\anaconda3\Lib\site-packages\transformers\models\sam_hq\processing_samhq.py:77: error: INTERNAL ERROR -- Please try using mypy master on GitHub:
  version: 1.8.0
  EXITCODE=2
  ```
  mypy follows imports out of `pyutilz.text.similarity` into the installed `transformers` package — which ships inline types, so `ignore_missing_imports = true` does not stop it — crashes there, and **aborts the whole run**. No `[[tool.mypy.overrides]]` entry sets `follow_imports` for any third-party package. Because the run aborts partway, the reported error set depends on traversal order: run 1 reported `llm/openrouter_provider/_provider.py:630 [no-any-return]` among its 5 project errors; **run 2 of the identical command did not report `_provider.py:630` at all**. The `--warn-unreachable --warn-unused-ignores --no-incremental` run reached further still and surfaced 46 project errors that neither earlier run mentioned. Note also that no run ever prints the `Success: no issues found in N source files` / `Found N errors in M files` terminator — the run simply stops.
- **Failure scenario**: A contributor commits on this machine. `mypy-full-blocking` runs `python -m mypy`, mypy exits 2 on the transformers crash, and pre-commit blocks *every* commit for a reason unrelated to their change. In the other direction — the dangerous one — if the crash lands before their file in traversal order, mypy never checks it at all and the blocking gate reports nothing, so a genuine type error is waved through by a gate that looks like it ran. Both directions are live today. The same abort-on-third-party-crash behavior can silently truncate the CI run the moment any dependency ships a module mypy 2.1.0 chokes on, with `advisory: false` giving false confidence.
- **Suggested fix**: Add `[[tool.mypy.overrides]] module = ["transformers.*"] follow_imports = "skip"` (extending to other heavy inline-typed optional deps as they surface) so a third-party crash cannot abort the project's own check. Separately, make the gate assert *completion* rather than only exit status — require the `Success: no issues found in 113 source files` line, so a truncated run can never be mistaken for a passing one.

### F02. [Medium] `download_in_parallel(urls_to_process: Sequence)` is annotated non-`Optional` while both its body and its docstring handle `None` — src/pyutilz/web/web.py:305
- **Disposition**: OPEN
- **Category**: annotation-vs-reality
- **Problem**: The signature is `def download_in_parallel(urls_to_process: Sequence, func: Callable, headers: Optional[dict] = None, ...) -> Optional[List]:` (web.py:304-311). The docstring at web.py:315-316 states "or None if `urls_to_process` is None/empty", and the body at web.py:320-321 is `if urls_to_process is None: return None`. mypy confirms the contradiction: `src\pyutilz\web\web.py:321: error: Statement is unreachable  [unreachable]` — the annotation makes the function's own documented `None` path provably dead. The `-> Optional[List]` return type is then justified only by a branch the parameter annotation declares impossible.
- **Failure scenario**: A caller holding an `Optional[Sequence]` — precisely the case the docstring invites — passes it. Under any strict-mode expansion covering `pyutilz.web` this is a hard `arg-type` error even though it is the documented, working runtime behavior. Conversely, a reader who trusts the annotation adds their own `if urls is None` guard upstream, duplicating a check that already exists inside. The annotation, the docstring and the code are three different contracts.
- **Suggested fix**: Change to `urls_to_process: Optional[Sequence]`, per CLAUDE.md rule 1/2 (match the annotation to what the function actually accepts and returns). The docstring and body are already correct and need no change.

### F03. [Medium] `remove_nas(obj: dict)` is annotated `dict` but recursively handles `list`, `str` and arbitrary values; three of its four branches are unreachable to the type checker — src/pyutilz/system/system/_common.py:32
- **Disposition**: OPEN
- **Category**: annotation-vs-reality
- **Problem**: `def remove_nas(obj: dict):` — a `dict` parameter and **no return annotation at all** — with a body that dispatches four ways (`_common.py:41-51`): `isinstance(obj, dict)` returns a dict comprehension, `isinstance(obj, list)` returns a list comprehension, `isinstance(obj, str)` returns `float(obj)` or the string, and `else` returns `obj` unchanged. mypy: `src\pyutilz\system\system\_common.py:43: error: Statement is unreachable  [unreachable]` — the `list` branch (and everything after it) is dead given the declared `dict`. The function's own recursion at line 42 (`remove_nas(v) for k, v in obj.items()`) passes arbitrary dict *values*, so the non-`dict` branches are not merely reachable, they are the dominant runtime path.
- **Failure scenario**: The declared type is wrong for the function's own recursive call site — a strict-mode expansion of `pyutilz.system` errors on line 42 immediately. Meanwhile a reader trusting the signature treats this as a `dict`-in/`dict`-out normalizer and is surprised when a scalar `float` or a bare string comes back. Because there is no return annotation, nothing currently catches the five-way return-type spread either — this is CLAUDE.md rule 2 ("match the return annotation to what the function actually returns") with the annotation simply absent.
- **Suggested fix**: Annotate honestly — `def remove_nas(obj: Any) -> Any:` at minimum, or `Union[dict, list, str, float]` in and out to match the four branches — and add the missing return annotation.

### F04. [Medium] `job_completed(data: Optional[str] = None)` is annotated `str` but every in-repo caller passes a `dict` — src/pyutilz/system/monitoring.py:59
- **Disposition**: OPEN
- **Category**: annotation-vs-reality
- **Problem**: `def job_completed(job_id: str, status: int = 0, data: Optional[str] = None, provider: str = "healthchecks.io", api_key: Optional[str] = None, blocking: bool = True):` (monitoring.py:59-61). The `monitored` decorator in the same module builds `data` as a **dict** — `if data is None: data = {}` then `data[duration_field] = round(timer() - start_time, duration_rounding)` (monitoring.py:153-155) — and passes it straight through at monitoring.py:164. - **Suggested fix**: Change to `data: Optional[dict] = None` (or `Optional[Union[dict, str]]` if the string form is genuinely intended to be supported), and update the docstring accordingly.

### F05. [Medium] Three `no-any-return` violations of CLAUDE.md rule 4 — unwrapped arithmetic / `.get()` chains returned from concretely-typed functions — src/pyutilz/performance/kernel_tuning/benchmark.py:209
- **Disposition**: OPEN
- **Category**: no-any-return
- **Problem**: Verbatim mypy output:
  ```
  src\pyutilz\performance\kernel_tuning\benchmark.py:209: error: Returning Any from function declared to return "float"  [no-any-return]
  src\pyutilz\performance\kernel_tuning\benchmark.py:221: error: Returning Any from function declared to return "float"  [no-any-return]
  src\pyutilz\llm\openrouter_provider\_provider.py:630: error: Returning Any from function declared to return "dict[str, Any]"  [no-any-return]
  ```
  `benchmark.py:209` is `return statistics.median(samples) * 1000.0 if samples else float("inf")` with `samples: list` declared at line 207 — unparameterized, so `statistics.median` returns `Any`. Line 221 is the same expression over `flat = [s for r in results for s in r]` derived from `results: list[list]` (line 214) — also unparameterized at the inner level. `_provider.py:630` is `return payload.get("data", payload) if isinstance(payload, dict) else {}` where `payload = resp.json()` is `Any`, and `isinstance` narrowing to a bare `dict` leaves `.get()` returning `Any`. All three are exactly the patterns CLAUDE.md rule 4 ("wrap the final returned value in the concrete constructor matching the declared return type") and rule 3 ("annotate list literals explicitly") name. `warn_return_any = true` is already configured, so these are live failures of the project's own gate — unreported today only because of F01's abort.
- **Failure scenario**: `time_backend`'s declared `float` is the value every downstream kernel-tuning and backend-dispatch decision compares against; `Any` means a non-numeric value introduced by a future `statistics`/backend change propagates silently into comparison logic instead of failing at the boundary. For `_provider.py:630`, `payload.get("data", payload)` can legitimately yield a `list` (OpenRouter's `data` field is not contractually an object) while the signature promises `dict[str, Any]` — a caller doing `result["total_cost"]` then gets `TypeError: list indices must be integers` at a site the annotation declared safe.
- **Suggested fix**: `samples: list[float]` and `results: list[list[float]]`, then `return float(statistics.median(samples) * 1000.0) if samples else float("inf")` at both sites. For `_provider.py:630`, narrow the extracted value rather than the container: `data = payload.get("data", payload) if isinstance(payload, dict) else {}` / `return data if isinstance(data, dict) else {}`.

### F06. [Medium] Two `arg-type` violations passing `Optional` values into non-`Optional` parameters — src/pyutilz/system/monitoring.py:164
- **Disposition**: OPEN
- **Category**: optional-narrowing
- **Problem**: Verbatim mypy output:
  ```
  src\pyutilz\system\monitoring.py:164: error: Argument "job_id" to "job_completed" has incompatible type "str | None"; expected "str"  [arg-type]
  src\pyutilz\system\single_flight_cache.py:137: error: Argument 2 to "get" of "Mapping" has incompatible type "None"; expected "_V"  [arg-type]
  ```
  In `monitoring.py:161-164`, `local_job_id = job_id` (from `monitored(job_id: Optional[str] = None)`), then `if not local_job_id: local_job_id = func.__name__`. `func` is an **unannotated** parameter of `decorator_logged(func)`, so `func.__name__` is `Any`; assigning `Any` into a variable mypy inferred as `str | None` does not re-narrow it, so the join at the call remains `str | None`. In `single_flight_cache.py:137`, the expression is `return default if default is not None else cache.get(key, default)` inside `get_or_fetch(self, cache: MutableMapping[_K, _V], key: _K, fetcher: ..., default: Optional[_V] = None) -> Optional[_V]` (lines 89-95) — the `else` branch is reached only when `default is None`, so `cache.get(key, None)` is passed against a `Mapping[_K, _V]` whose `get` overload expects `_V`.
- **Failure scenario**: `monitoring.py:164` is the CLAUDE.md rule-6 shape — annotate `func: Callable[..., Any]` in `decorator_logged` (the correct, independently desirable change, and the one that would also expose F04) and the `Any` escape hatch disappears, leaving a genuine unresolved `None` reaching `job_completed(job_id: str)`, whose body formats `job_id` into the monitoring endpoint URL and into every log line. For `single_flight_cache.py:137`, the branch is dead by construction: `default is None` there, so the whole expression reduces to `cache.get(key, None)`, which cannot return anything the preceding `if key in cache: return cache[key]` did not already return — it reads as a meaningful fallback but is a guaranteed `None`.
- **Suggested fix**: `monitoring.py` — annotate `def decorator_logged(func: Callable[..., Any]):` and write `local_job_id: str = job_id or func.__name__`. `single_flight_cache.py:137` — collapse the provably-dead branch to `return default`, or, if the lookup is deliberately retained for a subclassed mapping with side effects, make that explicit with `cast(Optional[_V], cache.get(key, None))` plus a comment.
