### F01. [High] `pip install pyutilz` documented as having "no hard deps" — it installs 9 packages including pandas — docs/index.md:23
- **Disposition**: OPEN
- **Category**: docs/correctness
- **Problem**: `docs/index.md:23` (the published documentation site's front page) says `pip install pyutilz  # core only, no hard deps`. `pyproject.toml:27-97` declares `[project.dependencies]` = `numba>=0.56`, `numpy>=1.20`, `joblib>=1.2`, `portalocker>=2.0`, `psutil>=5.9`, `pandas>=1.5`, `tqdm>=4.65`, `pympler>=1.0`, and `tomli>=2.0 ; python_version < '3.11'` — nine unconditional runtime dependencies, four of them (`numba`, `numpy`, `pandas`, `psutil`) heavyweight. README.md:21 states the same install line as `# core only (numba, joblib, portalocker)`, which is also wrong but only by omission; README.md:14 and docs/index.md:14 repeat the three-package framing in prose ("The core has few hard dependencies (`numba`, `joblib`, `portalocker` ...)"), followed by "so `pip install pyutilz` stays light".
- **Failure scenario**: A reader evaluating pyutilz for a size- or dependency-constrained context (a Lambda layer, a container image, a library that must not drag pandas into its consumers' resolver) reads "no hard deps", adds pyutilz, and only discovers at `pip install` time that they have pulled the entire numba+numpy+pandas stack. The claim is also the library's stated selling point in `pyproject.toml:8`'s package description, so it is load-bearing for the adoption decision.
- **Suggested fix**: Replace docs/index.md:23's comment with the real list (`numba, numpy, joblib, portalocker, psutil, pandas, tqdm, pympler`), sync README.md:21, and reword the README.md:14 / docs/index.md:14 prose from "few hard dependencies (numba, joblib, portalocker)" to the accurate set, keeping the "domain extras are opt-in" point, which remains true.

### F02. [High] `pre-commit install` is instructed in three docs but `pre-commit` is in no extras group — README.md:38
- **Disposition**: OPEN
- **Category**: docs/correctness

### F04. [Medium] CONTRIBUTING tells contributors to use `@pytest.mark.integration`, which is a collection ERROR under this repo's `--strict-markers` — CONTRIBUTING.md:221
