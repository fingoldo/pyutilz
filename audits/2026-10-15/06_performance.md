# 06 Performance and inefficiency audit (pyutilz, src/pyutilz)

Scope: read-only pass over src/pyutilz for work repeated per item, quadratic patterns, unbounded growth in long-running processes, whole-file reads, N+1 calls and numpy/numba fallbacks on hot paths. Cold-path micro-optimisations are excluded. Costs are estimates from code reading, not profiler runs.

Checked and found acceptable: module-level regex compiles (no per-call compile in hot paths), the bounded LRU and size-capped caches (`registry.py:107`, `factory.py`, `token_counter.py`, `single_flight_cache.py`), the per-key lock dict in `disk_cache.py` (reference-counted), `_cue_pattern` lru_cache, and `_HW_BUSY_CACHE`.

## Verdict

The codebase is generally careful about hot-path cost. Caches are bounded or reference-counted, regexes are precompiled, and the earlier audit rounds fixed several unbounded-growth cases. The findings that matter are P-01, a lock-held O(window) trim on every proxy request that scales with request rate, and P-02, unbounded sampling lists in a long-running monitor. P-03 is a real memory and time cost for large batch loads, but it is a trade-off rather than a defect. P-04 and P-05 are minor and only show up on pathological inputs or failure storms. No numba or numpy kernel falling back to a Python loop was found on a hot path in this pass.

## Disposition (implementation, 2026-10-15)

- P-05: RESOLVED. `src/pyutilz/system/resilience.py` `DeadLetterQueue.queue` is `collections.deque(maxlen=max_size)`; `add` appends only, and `get_recent` slices the reversed deque. Test: `test_p05_dead_letter_queue_is_bounded_deque`.
