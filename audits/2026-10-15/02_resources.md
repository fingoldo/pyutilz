# Audit 02: resource release and handle lifetime

Scope: read-only audit of `src/pyutilz` for files, sockets, HTTP sessions, DB connections and cursors (including named server-side cursors), SQLAlchemy engines, pools, locks, temp files/dirs, subprocesses, browser drivers, and generators holding resources. The existing gate `tests/test_meta/test_resource_release_gate.py` was read as well. No code, tests or formatters were touched.

## Verdict

Three real defects and one reproducible gap in the gate. The most important is R-01: reconnect silently drops the old psycopg2 connection, so the socket lives until GC, and other threads' cached cursors can keep it alive. R-03 is a narrow but real server-side cursor leak on the retry paths, and the gate does not detect it because the cursor acquisition is behind the facade (as the gate's own comment states). The rest of the resource paths I checked are correctly released on every path (see below). No P0 or P1 findings.

## Resource kinds checked with no finding

- Named server-side cursor fetch-then-close in `basic_db_execute` success path and `_finish_execution` (`execution.py:~167-185`, with `finally` at the fetch): closed on fetch error and on success.
- `InternalError` branch closes the named cursor (`execution.py:~242-249`, via `_close_cursor_after_internal_error`).
- Unnamed per-thread cursors: cached by design, not a leak.
- `execute_alchemy`: `with conn_alchemy.connect()` on every attempt (`execution.py:704-707`).
- `psycopg2_pool.py`: `_ensure_connection` uses `with conn.cursor()` (`:117`); `release_connection` returns or closes the connection in every branch (`:252-272`); `pool.putconn` is in `except`/`finally`.
- `connect_to_db` failure path closes a connection it opened in this iteration (`connection.py:196-203`).
- `redislib.py`: `rconnect` closes the previous client (`:70-72`); `rclose` in `finally` (`:79-84`).
- `web/proxy/session.py`: `curl_session` and `requests_session` are `@contextmanager`s with `try/finally: s.close()` (`:64-66`, `:113-115`).
- `web/web/fetching.py` `get_new_session`: old session closed on rotation (`:~402-410`).
- `web/web/downloads.py` `_download_attempt`: streamed response closed in `finally` (`:206-207`), file opened in `with` (`:201`).
- `web/proxy/decodo.py`: `with requests.Session()` (`:324`).
- `core/pythonlib/filesystem.py` `open_safe_shelve`: `portalocker.Lock` is a `with`, and `db.close()` plus fsync run in `finally` (`:286-297`).
- `core/pythonlib/filesystem.py` `suppress_stdout_stderr`: devnull `with`, stream restore in `finally` (`:300-320`).
- `core/disk_cache.py` `_get_key_lock`: refcount decrement in `finally` (`:426-433`); `ThreadPoolExecutor` in `with` (`:169`).
- `core/disk_cache.py` and `core/safe_pickle.py` atomic writes: `os.open` / `os.write` / `os.close` paths close in `finally` (cache_sweeping `:77-87`, `:101-113`).
- `performance/kernel_tuning/cache/cache_sweeping.py` marker claim: fd closed in `finally` (`:86-87`, `:112-113`), temp marker removed in outer `finally` (`:115`).
- `web/browser.py` plugin fd: `os.close(plugin_fd)` immediately after `mkstemp` (`:327`).
- `web/browser.py` `close_browser` and `LoginAndGetCookies` restart: `.quit()` (not `.close()`), so the driver process is ended (`:158`, `:660`).
- `llm/claude_code_cli.py` `run_cli`: `subprocess.Popen` used as a context manager (`:~337-357`); `_reap_process` kills the tree, waits, and joins readers in `finally` (`:~407-420`). `_write_prompt` closes stdin in `finally` (`:~354-363`).
- `llm/claude_code_provider.py`: `child_cwd` from `mkdtemp` at `:785` is removed in the `finally` at `:~823-824`, and the system-prompt file is removed in the same `finally`.
- `llm/_messages.py` image temp dir: removed in `finally` (`:233`), so it is released even when the caller's body raises.
- `system/parallel.py` `mem_map_array`: one shared temp dir, removed by an `atexit` handler (`:40-46`). Intentional.
- `core/serialization.py` and `database/db/connection.py` are in the gate's exempt list. I read their release logic and it is correct as written (the `os.close` in `except`, the `conn.close` in `except`).
- `database/db/sqlite.py`: `open(schema_fpath)` in `with` (`:~55`); `executemany` failure rolls back (`:100-102`).
- `cloud/mailru.py` paging generator holds no resource (`:116-127`).
- `dev/attempt_archive.py` `mkstemp` fd: the write path is correct (not read in detail; flagged only by the scanner's pattern, not by inspection).

## Disposition (implementation, 2026-10-15)

- R-01: RESOLVED. `src/pyutilz/database/db/connection.py` `connect_to_db`: after the new psycopg2 connection succeeds, the replaced one is closed by `_close_replaced_connection`. Caveat: other threads' thread-local cursor caches still hold cursor objects on the closed connection until they next call `get_cursor()`; they then get an error and the normal retry path reconnects. Test: `test_r01_reconnect_closes_replaced_connection`.
- R-02: RESOLVED. `connection.py` `_dispose_previous_engine()` runs before both `create_engine` calls (postgres and mysql). Tests: `test_r02_*`.
- R-03: RESOLVED. `src/pyutilz/database/db/execution.py` `basic_db_execute`: `_close_local_named_cursor` is called on the OperationalError/InterfaceError branch (before retry or raise) and on the DuplicateTable branch. Test: `test_r03_named_cursor_closed_on_operational_error_retries`.
- R-04, R-05, R-06: not in this task's file list; left to their owners.
