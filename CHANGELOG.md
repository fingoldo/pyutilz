## [Unreleased]

### Added
- Ten further `code_audit` scanners, shipped in five batches: `column_no_write_path` (a table column that is read but never written by any code path); `patch_target_is_a_reexport` (a `mock.patch` aimed at a re-exported name, which leaves the real definition unpatched); `test_asserts_against_production_constant` and `source_text_assertion` (test-quality defects -- an assertion that restates the production constant it should pin, and an assertion made against source TEXT rather than behaviour); `sentinel_cached_as_answer` and `shielded_resource_release_race` (state that outlives the failure that made it); `count_then_fetch_same_table`, `sql_selects_unread_column` and `sql_aggregate_before_cast` (work the database does twice or not at all); and `docstring_numbers_moved_to_config` (a docstring still naming a number whose home is now a config value).
- `pyutilz[speedups]` (orjson), included in `[all]` and installed by CI. Nothing imports orjson unconditionally - every use site falls back to the stdlib encoder - so the group only ever makes an existing path faster, and it was previously undeclared, meaning the measured 25-32x `json_pg_dumps` win reached only the environments that happened to have it.
- CI now runs on Windows and macOS, not just Linux: `ci.yml`'s test matrix is ubuntu-latest x windows-latest x macos-latest across all seven supported Python versions (3.8 and 3.9 on macos-15-intel, since setup-python publishes no arm64 build for them). The library has real platform-specific code - wmi/pywin32 probes, a cp1251 console path, POSIX permission bits, portalocker file locking - and a Linux-only matrix could never exercise the other two thirds of those branches. Every `run:` block in that job is pinned to bash so the Windows leg parses them the same way. `py-ci-shared`'s own self-ci.yml got the same three-OS matrix.
- Three `code_audit` scanners distilled from the 2026-09-01 wide mlframe audit, where 229 findings turned out not to be 229 independent defects: three shapes accounted for a third of them, each invisible at its own call site. `scan_additive_epsilon_denominator` flags `x / (d + 1e-12)`, which reads as a division guard and is not one -- the pad is harmless only while the denominator's natural scale stays far above it, an assumption about the DATA, and it does not guard the division but REPLACES the answer with a plausible finite value for every input; measured consequences in that audit were a slope reported as exactly 0.0 against a true 1.0, a spectral ratio wrong by 237x purely from rescaling the same signal, and a skew of 2.0 read as 0.25, which flips a basis-routing branch. `scan_non_neutral_except_fallback` flags an `except` handler that returns or assigns a non-neutral literal without logging above debug level: the substituted value is indistinguishable downstream from a real result, and is routinely non-neutral in the direction that DISABLES the check it feeds -- `0.0` for a max error is the BEST possible max error, `return True` from a VRAM probe is the value that ALLOWS the upload, `-inf` GUARANTEES rejection -- so a safety mechanism switches itself off in exactly the conditions that trip it; `None` and `ImportError`-only handlers are exempt, and it keys on the substituted VALUE rather than on breadth of catch (`broad_except_swallow`) or escalation (`log_only_except`). `scan_nondiscriminating_test_functions` flags a `test_*` function that cannot fail for the reason it names -- no assertion at all, every assertion behind an `if`, `except AssertionError: pass`, an `if` body of `pass`, or an imperative `pytest.xfail(...)` discarding the measurement just taken; where `vacuous_assertion` judges the assertion EXPRESSION, this one judges structure, so the two do not overlap. Each is verified against an injected violation of every shape it claims to catch and against healthy code it must not flag -- a checker for tests that cannot fail would otherwise be an instance of the very defect it exists to find.
- Four preventive meta-tests, each closing a defect class that recurred in every audit wave rather than a single finding. `tests/test_meta/test_shared_checks_wired.py` consumes the seven `py_ci_shared` checks this repo had never wired up (module-LOC budget, per-job CI `timeout-minutes`, reviewed `continue-on-error`, entry-point resolvability, markdown-link targets, git-dependency pinning, CI reachability of every `tests/` subdir) — `ci.yml`'s `ci-required` job gained the `timeout-minutes` it was missing as a result. `tests/test_meta/test_gate_integrity.py` requires every scope narrowing on a blocking gate (`--ignore C901`, a `files=` regex, a `[tool.ruff] exclude`) to carry a written reason in an in-repo declaration map, keyed by tool and flag rather than by line, and fails on a stale declaration as well as an undeclared narrowing; it also asserts the CI coverage floor equals `[tool.coverage.report] fail_under`. `tests/test_meta/test_prose_numeric_claims.py` and `tests/test_meta/test_docs_inventory_parity.py` replace hand-typed counts and inventories in the prose files with computed parity assertions.
- The whole-project mypy hook now runs through `py_ci_shared.mypy_gate` instead of `python -m mypy`. mypy exits non-zero on an internal crash, but a crash can also truncate a run that would otherwise pass, so an exit code alone cannot distinguish "checked 216 files, found nothing" from "aborted inside a third-party stub after 40". The wrapper requires mypy's own `Success: no issues found in N source files` line, and `--min-files 200` additionally fails a run whose scope has silently narrowed.
- `scripts/prove_meta_checks.py` — builds a defective copy of the repo's config/prose surface under a temp dir, one mutation per historical finding, and asserts each new check fires on it. Run it after touching any of the four meta-tests above; a check that cannot be shown to catch the thing it exists for is decoration.
- `pyutilz.web.proxy.decodo.ALLOWED_LOCATIONS` — the account's full residential exit inventory (164 `gate.decodo.com` endpoints across 78 countries, as returned by Decodo's locations API), each entry carrying its `country-xx-city-yyy` username segment plus the random port (new IP per request) and the sticky port range (one IP for the life of a session). The exit is selected by rewriting the proxy USERNAME rather than by a separate setting, so a caller rotating exits has nowhere else to look the segment up at runtime. Deliberately the COMPLETE inventory; which subset a given job may use is the job's policy, not this module's.
- `pyutilz.web.proxy.decodo.ALLOWED_COUNTRIES` — the 143 exit countries available on the DATACENTER endpoint (`dc.decodo.com`). Not derivable from `ALLOWED_LOCATIONS`: city-level targeting is a residential-gateway feature, and appending a city segment to a datacenter username raises `ProxyError` (verified against a live account), while every `ALLOWED_LOCATIONS` entry names a city. The leading unpinned entry is a real option — omitting the country segment gives an unpinned exit — not a placeholder.
- `pyutilz.data.git_checkpoint_cache` — a git-tracked gzip backup for a machine-local cache, with auto-restore when the local copy is missing or empty. Extracted from a downstream project's LLM-cache durability fix, where the identical pattern (refresh a checkpoint on every write, auto-restore from it when `~/.cache` is wiped/moved) had been copy-pasted four separate times across that codebase's various LLM-backed caches before being pulled out here. Two shapes: `write_json_checkpoint`/`read_json_with_checkpoint_fallback` for an in-memory JSON-serializable object rewritten wholesale each write (the common `{id: verdict}`-style cache), and `write_bytes_checkpoint`/`read_bytes_with_checkpoint_fallback` for a cache that is itself a flat file on disk (a JSONL ledger, a SQLite dump) — checkpointed as a byte-for-byte gzip copy, no re-serialization. Both write paths use the same atomic-rename discipline as the rest of this package. Not a substitute for a real backup strategy on irreplaceable data — scoped to a locally-regenerated cache (an LLM call result, a scraped API response) whose loss costs re-computation time/money but not correctness.
- `pyutilz.dev.code_audit.scan_domain_vocabulary_leak` — a ratchet on the cost of a refactor you have deliberately NOT done yet. A codebase grows one product, a second product is meant to reuse its machinery, and the reusable half gets named ("the provenance envelope", "the corroboration rule") long before it is extracted — correctly, because a speculative refactor with no second consumer rots. What is not safe to postpone is knowing whether the split is still cheap: entanglement arrives one identifier at a time, in code nobody thought they were making domain-specific. The caller declares a `BoundarySymbol` list (symbols claimed domain-neutral) plus a vocabulary of domain terms, and any term inside a boundary symbol's source span — identifier, string, docstring or comment — is a finding. Symbol granularity, not module: before the split the neutral concept and the domain concept live in the same file by definition, so a module-level rule reports every such file and says nothing. Prose is scanned because a docstring is where a reader's model of "what this code is about" is formed. A companion `boundary_symbol_missing` (P1) fires when a declared symbol no longer exists, so a rename cannot silently empty the boundary and leave the check passing by vacuity; finding details lead with symbol and term and put the occurrence count after the ` -- ` separator, so a ratchet keyed on the truncated head tells two leaks in one symbol apart without failing the build when a count merely goes DOWN. `OPT_IN_ONLY`: silent until configured, since a boundary is a claim only the project can make.
- `pyutilz.dev.code_audit.field_text_agreement` — a deterministic cross-check for a defect shape the AST scanners cannot see: **a structured field that duplicates information also present in free text, where the two are never compared.** Each half validates alone (the enum against its member list, the prose against the source it was copied from) so the pair can disagree indefinitely; found in a forensic knowledge base where `temporal_class = "postmortem"` sat beside an endpoint named "vital hanging". A field/text pair is a `FieldTextRule` table entry — cue phrases per field VALUE, positional `anti_cues` for homographs ("vital hanging" vs "injury to vital organs"), `partitions` for values that can co-hold, or a `resolver` when a caller's dependency parse must decide whether a cue GOVERNS the claim rather than merely appearing near it. Three outcomes, not two: `AGREE`, `CONTRADICT` and `UNCHECKABLE`, with `FieldTextReport.coverage` published beside the counts, because a checker that silently passes every row it could not read reads as a clean bill of health it has not earned; a neutral field (`na`, `unstated`) beside a real cue is a CONTRADICT of kind `unfilled_but_cued`, not agreement. Deliberately NOT registered in `SCANNERS`: every scanner honours `(root: Path, exclude_dirs) -> list[Finding]` and a record-level checker cannot, so registering it would break `run_all` rather than extend it — being unregistered it also cannot alter any project's committed baseline on upgrade, which is what `OPT_IN_ONLY` exists for. Hits render as `Finding` objects. Cue vocabularies are domain knowledge and stay with the caller.
- **Strict JSON-schema output** across the OpenAI-compatible providers: `generate()`, `generate_stream()` and `generate_json()` accept `json_schema=` and send `response_format={"type": "json_schema", ...}`, which CONSTRAINS generation instead of merely asking for valid JSON — a closed enum (fixed vocabulary, fixed severity levels) becomes impossible to violate rather than discouraged by the prompt. Capability is advertised by the new `LLMProvider.supports_json_schema()` (False by default, True for OpenAI-compatible endpoints, per-model catalogue check on OpenRouter requiring `structured_outputs`). A model without support degrades to plain JSON mode with a warning so mixed-model sweeps stay runnable, and `last_json_schema_applied` tells the caller whether the guarantee actually held — claiming an unverifiable guarantee would stop callers validating the enum they believe was enforced.
- `[dataframes]` extras group (`pandas` + `polars` combined); `[all,dev]` is now the recommended one-line install.
- `pyutilz.dev.code_audit` — AST-based scanner + CLI for four recurring bug classes (mutable defaults, late-binding closures, `x or DEFAULT` footguns, silent broad-except swallows). `python -m pyutilz.dev.code_audit <root>`.
- Kernel-tuning cache rewritten as immutable per-`(host, kernel, code_version)` files — no `filelock`, no lost updates under concurrent writers; legacy monolithic caches migrate automatically.
- `pyutilz.dev.benchmarking` sweeps gained `ranking="robust"` (default): interleaved min-over-reps ranking that stays correct on a contended GPU, where the old mean-based ranking could pick the wrong "fastest" config.
- Unified `get_account_credits()` / `check_account_limits()` across every LLM provider: `get_account_credits()` is native for OpenRouter/DeepSeek only; `check_account_limits()` is native for OpenRouter, header-fallback for Anthropic/DeepSeek, and an informative `NotImplementedError` for OpenAI/xAI/Gemini/Claude Code.
- OpenRouter provider: model catalogue browsing, live health pre-flight (`check_model_health`, `is_model_healthy`), full usage/cost capture (`fetch_generation_stats`, `last_call_summary`), authoritative per-request billed cost.
- `thinking=` on `generate()`/`generate_stream()` now accepts `"low"/"medium"/"high"/"minimal"` effort strings (previously bool-only), normalized per-provider.
- `tqdmu_lazy_start()` — starts the elapsed-time bar on first iteration, not construction.

### Changed
- `code_audit`'s catalogue and attribute surface are now DERIVED from the scanner registry instead of hand-maintained beside it. `describe_scanners()` / `render_check_catalogue()` assemble every registered check's one-line summary from the scanner's own docstring and mark `OPT_IN_ONLY` membership automatically, printed by the new `python -m pyutilz.dev.code_audit --list-checks`; the package docstring, which had fallen thirty checks behind and marked one opt-in check out of sixteen, now points at that instead of claiming to be the catalogue of record. The submodule-cleanup block that kept the facade's `dir()` flat is likewise computed rather than a hand-listed tuple, which had gone fifteen submodules stale.
- One `is_test_file()` in the scanner package's shared `_base` module replaces thirteen private "is this a test file" predicates that answered the question six mutually incompatible ways. A project whose tests live in a `tests/` directory but do not carry the `test_` prefix used to be scanned by five of the test-focused checks and skipped silently by six others, with no error either way, so partial coverage and a clean result looked identical. The shared definition is the widest of the six (either pytest naming convention, or a `tests`/`test` path component) and takes an optional glob for a custom layout. Six further duplicated private helpers (`is_cached`, `is_locals_or_globals_call`, `module_level_names`, `dotted_name` and friends) moved to `_base.py` for the same reason - the decorator set that counts as "cached" was two different sets in two scanners - and the four pairs that only shared a NAME were renamed apart.
- `field_text_agreement` moved out of `pyutilz.dev.code_audit` to `pyutilz.dev.field_text_agreement`. It checks in-memory records, not source trees, so its presence inside a package whose every other module is a `scan_*(root, exclude_dirs) -> list[Finding]` made that contract false and left the API undiscoverable to anyone driving the package through `get_scanners()`. `pyutilz.dev.code_audit.field_text_agreement` remains as a re-export shim and the facade still re-exports every public name, so no import path changed.
- Every LLM provider's `_resolve_pricing` now returns one `Pricing(input, output, cache_hit)` record (`llm/openai_compat.py`). The same private method name previously carried a 2-tuple in xAI and a 3-tuple in DeepSeek, so the accessors indexed `[1]` and `[2]` for the same quantity; a sixth provider copying one file's tuple shape and its neighbour's accessors would have reported the cache-hit rate as the output rate, with nothing raising and only a silently wrong USD figure to show for it. The cache-hit fallback is implemented once on the base class, and `cache_hit=None` distinguishes "this provider publishes no cached-input rate" from a rate of zero.
- `thinking=False` on the LLM providers now asks for no reasoning at all, rather than for a minimal reasoning budget: the old mapping still billed 13-348 reasoning tokens per call where the caller had explicitly asked for none. Separately, a length-capped completion that came back empty is now reported as a truncation (`LLMTruncationError`) instead of raising the generic empty-completion error, so a caller retrying with a larger cap can tell the two apart. Distinct from the `thinking=` effort-string change logged below.
- README's `[web]`, `[nlp]` and `[dev]` extras descriptions now list every member of their group (previously omitting `grequests`, `fake-useragent`, `inflect`, `emoji-data-python` and the six pytest plugins), CONTRIBUTING's coverage-omit list names the scheduling package by its full path from the source root, which now resolves, and the memory-reduction figure in README carries the date it was measured. All four were found by the new checks, not by reading.
- `pyutilz.dev.dashlib.create_tabs` now wraps the tab-content area in a `dcc.Loading` overlay (new `show_loading` argument, default `True`). A dbc tab HEADER switches the instant it is clicked — that is client-side state — while the body waits on the Dash callback, which can be seconds when a tab queries a large database. The user is left looking at the new tab's header above the PREVIOUS tab's content, which reads as "this tab is done and looks like the last one" rather than "still loading". The overlay must wrap the div whose children the callback replaces, not the returned content: by the time that content exists, the wait is already over. `delay_show=250` suppresses the spinner for callbacks that finish quickly, so tabs that were already fast do not gain a distracting flash. Pass `show_loading=False` to opt out.
- **Packaging metadata overhaul** (2026-09-02 packaging + dependencies audit). No API change, but several install commands and assumptions move:
  - `py-ci-shared` is no longer in the `[dev]` extra. A PEP 440 direct reference (`name @ git+https://...`) anywhere in project metadata makes every PyPI upload fail with `400 ... Can't have direct dependency`, and `twine check` passes it silently. It now lives in the new **`requirements-dev.txt`**; contributor tooling installs with `pip install -e ".[dev]" -r requirements-dev.txt`. `publish.yml` gained a gate that unzips the built wheel and fails the release if a direct reference ever reappears in `Requires-Dist`.
  - Core `[project.dependencies]` is now nine packages — `numba`, `numpy`, `joblib`, `portalocker`, `psutil`, `pandas`, `tqdm`, `pympler`, plus `tomli` below Python 3.11 — each with its rationale recorded inline in `pyproject.toml`. Documentation that still described `pip install pyutilz` as "no hard deps" / "numba, joblib, portalocker" has been corrected.
  - Every redeclaration of a core dependency was removed from the extras groups (pandas from `pandas`/`polars`/`database`/`nlp`/`system`, tqdm+pympler from `pandas`/`polars`/`system`, numpy from `dev`), so a version floor is stated exactly once. **`[stats]` is now an empty documented alias** (`stats = []`) — its only member, numpy, is core — and keeps working purely for discoverability.
  - `[all]` = `pandas,polars,database,web,cloud,nlp,llm,system,stats,speedups`, and `pyproject.toml`'s `all` comment is now the single source of truth for the four deliberate exclusions: `gpu` (PyPI's cupy is sdist-only, so the extra triggers a full local NVCC build), `dash`, `prefect` and `tensorflow`. Consequence: `pip install pyutilz[all]` canNOT import `pyutilz.dev.dashlib` or `pyutilz.system.scheduling.prefect`.
  - Python-version constraints moved out of CI shell into metadata: `spacy>=3.0 ; python_version >= '3.10'` (`nlp`) and `google-genai>=1.0 ; python_version >= '3.9'` (`llm`), joining the existing `black`/3.10 marker in `[dev]`.
  - `pypiwin32` dropped from `[system]` (it was listed in the 1.0.0 release notes and is no longer declared anywhere).
  - PEP 639 licensing (`license = "MIT"` + `license-files`, the `License :: OSI Approved` classifier dropped, `build-system.requires` raised to `setuptools>=77.0`, `wheel` dropped since `setuptools.build_meta` declares it itself), a new `MANIFEST.in` so the sdist ships tests + CHANGELOG, `strict: true` in `mkdocs.yml`, and `timeout-minutes` on the publish workflow's jobs.
  - Note for contributors: `pre-commit` and `vulture` are still declared in no extras group and no requirements file — install them explicitly (`pip install pre-commit vulture`) or `pre-commit install` and the blocking `vulture-blocking` hook fail on first use.

Black is applied repo-wide via `py_ci_shared.black_filtered_apply` (shared with mlframe; installed from `requirements-dev.txt`), which excludes two Black behaviors project convention keeps by hand (arg/collection-list explosion, blank-line insertion); a dedicated `Black (filtered)` CI workflow + badge tracks it.

README/docs now render three codecov badges (plain, `numba-disabled`, `combined`).
- `py.typed` marker added — pyutilz imports now type-check for real in downstream consumers (mypy previously treated every import as `Any` across the package boundary with no marker present).
- `pyutilz.dev.code_audit` gained a redundant-test-fit-call scanner (5th check): flags an identical call to an underscore-prefixed local helper made from 2+ different `test_*` functions in the same file, since the call is deterministic and every occurrence after the first recomputes the same result.

- `pyutilz.system`'s `parallel`/`monitoring`/`hardware_monitor`/`UtilizationMonitor` submodules are now resolved lazily (PEP 562 `__getattr__`) instead of eagerly imported, so `import pyutilz.system` no longer forces `[system]`'s pandas/psutil/tqdm stack onto callers who only need `pyutilz.system.system`. User-visible effects: a missing `[system]` dependency now raises at first attribute access (`pyutilz.system.parallel.<anything>`) rather than at `import pyutilz.system` time, and these names are absent from `dir(pyutilz.system)` / the module `__dict__` until first accessed.
- `pyutilz.dev.meta_test_utils.capture_signature()` now also captures each parameter's default *value* (for bool/int/float/str/None/tuple-of-those; other types collapse to a stable placeholder) — previously only `has_default` was recorded, so a silent default-value flip (e.g. `verbose: bool = False` → `True`) produced a byte-identical signature and was invisible to `test_api_stability.py`'s drift detector.

### Fixed
- Security wave (2026-09-03 audit `audits/implemented/2026-09-03/02-security.md`, 12 findings fixed, 1 rejected). `start_selenium()` no longer passes Chrome `--no-sandbox` unconditionally: it is passed only for a uid-0 process, where Chrome refuses to start otherwise, and forced either way via the new module-level `no_sandbox` (`init(no_sandbox=True)`) - a library whose purpose is visiting untrusted sites had the renderer sandbox off for every caller on every platform. The proxy-auth extension's host/port/user/password are escaped with `json.dumps()` (and `int()` for the port) instead of being interpolated raw into the JS of an extension holding `webRequest`+`webRequestBlocking` over `<all_urls>` - a password containing a `"` silently disabled proxy auth, and a hostile one executed arbitrary JS in that context. `urlopen_checked` now drops `Authorization`/`Proxy-Authorization`/`Cookie` on a redirect that crosses to a different host (same-host hops keep them), so a caller's API token is no longer re-sent to whatever host a `302` names. `logged()` routes both its persisted sinks - the `parameters` dict and the raw exception text - through `pyutilz.text.secrets_scrub.redact_secrets` plus a name-based credential filter, instead of protecting three hardcoded names. `redact_secrets` itself now catches quoted/JSON keys (`{"api_key": "sk-..."}` previously passed through completely unredacted). `CachedHttpClient` gained `max_bytes` (64 MiB default) and `unserialize()` gained `max_output_bytes` (4 GiB default, incremental decompression), so neither an endless response body nor a zlib bomb can allocate without limit. LLM API keys are no longer read from whatever `.env` sits in the process's current directory - pass `get_llm_settings(env_file=...)` or set `PYUTILZ_LLM_ENV_FILE`, and the file actually read is logged. Every OS-probe binary in `pyutilz.system.system` is resolved through `shutil.which` to an absolute path (Windows' `CreateProcess` searches the current directory before `PATH`). `code_audit`'s `_safe_parse` catches `RecursionError`/`MemoryError`, so one deeply-nested generated file skips instead of killing a whole scan, and the Claude Code CLI backend carries the same tool-use tripwire as the SDK backend. A weekly `pip-audit` workflow restores the dependency-advisory signal that Dependabot's disabled `pip` ecosystem stopped providing.
- `ClaudeCodeToolUseError` was the one LLM exception defined outside `llm/exceptions.py` and the only one not rooted at `LLMProviderError`, so the domain's documented catch-all did not catch it - and its own docstring calls it "a security event to surface to the caller", making it the error the design most wants surfaced and the one that escaped the handler callers are told to write. It now lives in `llm/exceptions.py` as `(LLMProviderError, RuntimeError)`, keeping the "not an OSError, so the retry arm cannot swallow it" property, and is exported from `pyutilz.llm`. The guard test that missed it walked one module's `vars()`; it now walks every module in the llm, database and web domains.
- `OpenRouterProvider` billed every cache-hit token at the full input rate: it tracks `last_cache_hit_tokens` more carefully than any sibling but had no `_cache_hit_cost_per_1m` override, so a long-context conversation with a high cache-hit ratio reported a `cost_usd` several times the true charge. It now reads OpenRouter's own `pricing.input_cache_read` from the model catalogue; a model whose entry omits the field keeps the documented input-rate fallback rather than a fabricated zero.
- `import pyutilz.data as d; d.pandaslib` raised `AttributeError` while `from pyutilz.data import pandaslib` and `from pyutilz.data import *` both worked - three spellings of one import, two of which resolved, so a downstream module using only the attribute form failed at runtime with no import-time warning. `data`, `dev`, `text`, `database` and `core` now carry the same lazy PEP 562 `__getattr__` `performance` and `system` already had, and a meta-test asserts every `__all__` entry of every subpackage is attribute-reachable.
- `pip install` was broken on Python 3.8 and 3.9, both of which this package declares support for. The PEP 639 licence migration landed earlier in the same wave requires setuptools>=77, and the newest setuptools published for 3.8 is 75.3.4, so the source build could not even start; separately the exact `mypy==2.3.1` pin in `[dev]` has no 3.8/3.9 release. The licence metadata is back on the deprecated table form until 3.8 support is dropped or setuptools 2027-Feb-18 removal nears, and the mypy pin is marker-gated to 3.10+, where the gate actually runs.
- Hardware monitoring collected nothing at all on macOS, and `get_system_info` silently dropped its CPU/RAM statistics there. psutil defines `cpu_freq` conditionally - it is absent from the module on backends that do not implement it, macOS among them - so calling it raised `AttributeError` on every sample; the swallow-and-continue handler dutifully logged and moved on, and `stop()` still returned as if all was well. Platform-gated psutil functions are now feature-detected once in a new `system/psutil_compat.py`, an unmeasurable clock records nothing rather than a fabricated 0.0 MHz that would average in as a real reading, and `get_average_utilization()` reports which metrics the platform cannot provide.
- `datetime.utcnow()` replaced everywhere: deprecated from Python 3.12. Every site kept its naive-UTC value, because each subtracts against a caller-supplied or `strptime`-derived naive datetime and an aware one would raise instead.
- Facade packages no longer `del` their submodule bindings. The deletion made `dir()` and every dotted access depend on import ORDER: any later `import <pkg>.<submodule>` or `mock.patch` target re-set the attribute as a side effect, while code running before that saw an `AttributeError`. A `__dir__` hook reports the same curated surface without removing the real attribute - the idiom `pyutilz.system.system` already used.
- Two polars calls and one BeautifulSoup call were on deprecation paths that only warn against newer versions than the dev box had, so the new warnings-as-errors policy failed CI and passed locally: `explode()` now states `empty_as_null=True` and horizontal `concat` uses `horizontal_extend`, both behind version probes since the declared floor is polars>=0.19, and `findAll` becomes `find_all`.
- `pyutilz.text.humanizer.humanize()` no longer corrupts the SECOND occurrence of a repeated protected span. Protected spans were remapped onto the cleaned text with an unanchored `text.find(snippet)`, which returns the first occurrence every time — so a term the writer used twice ("PostgreSQL" in two sentences) had occurrence one protected twice and occurrence two not at all, leaving it exposed to typo injection. Spans are now sorted and re-located with a forward-only cursor so each occurrence is claimed at most once, with a global-search fallback so one span deleted by an earlier cleaning stage cannot cost every span after it. Surfaced as a ~10% flaky test in a caller generating client-facing text, which would otherwise have shipped a mangled technical term at random with nothing in the output or logs to indicate it.
- LLM context reserve widened from 15% to 30% of the estimated input. `count_tokens` estimates the input while the upstream counts it for real, and the two disagree by a fraction that grows with the prompt: a measured 20.9% undercount on gpt-oss-120b (19,920 estimated vs 24,077 real) pushed granted budget + real input to 132,241 against a 131,072 window, and the provider rejected the whole call with HTTP 400 before generating a token. This changes the effective output budget of every call that hits the clamp — the reserve only binds on a large input, and the surviving budget stays far above what these callers request, while being a few hundred tokens short costs the entire call. The regression test now carries both measured incidents as a table rather than only the first.
- `polars_df_info` no longer reports a `RangeIndex` line. The summary was copied verbatim from pandas' `.info()` output ("RangeIndex: N entries, 0 to N-1"), but a polars DataFrame has no index at all, so the line described a structure that does not exist and invited readers to reason about index-alignment/reindexing semantics that cannot apply. Replaced with a plain "Rows: N" — a user-visible output-shape change for anyone parsing that text.
- LLM providers now clamp the output budget to what the context window actually allows (`LLMProvider.fit_max_tokens_to_context`, applied in the OpenAI-compatible `generate`/`generate_stream` plus Gemini and Anthropic). A model's advertised output cap can EXCEED `context_window - input` — llama-3.3-70b offers a 128k output cap inside a 131k window — so `max_tokens=0` ("use provider max") previously built an impossible request that the upstream rejected outright with `HTTP 400: maximum context length is 131072 tokens, however you requested about 133164`, before generating a single token. An explicitly-passed oversized budget is clamped the same way. Related: the OpenAI-compat path now awaits `_async_prepare()` unconditionally, since the context clamp reads `context_window` (a sync property that may fetch the model catalogue) on every call, not only when the budget is auto-selected.
- **BREAKING**: 14 accidentally-public leaked-import symbols removed from `pyutilz.image` / `logginglib` / `numpylib` / `parallel` (never intended API; real homes documented in each symbol's replacement). This removes importable names that worked in 1.0.0 — pin/upgrade accordingly.
- `pyutilz/web/browser.py` importing a nonexistent `pyutilz.web.pythonlib` (correct home: `pyutilz.core.pythonlib`).
- `pyutilz.core.pythonlib.get_parent_func_args`: perf fix for frame-locals access on the caller's-stack read path.
- `pandaslib.frames.remove_stale_columns` (deprecated alias for `get_non_stale_columns`) now actually raises `DeprecationWarning` on call — the docstring said "Deprecated" but nothing ever warned at runtime.
- **Third full-repo audit wave** (2026-09-02): 223 findings raised across ten directions — architecture, security, packaging, test-suite quality, documentation, typing/lint hygiene, the three domain sweeps (core/dev/system, data/stats, database/web/cloud/llm/text) and performance — recorded finding-by-finding with its disposition under `audits/implemented/2026-09-02/`. The domain and packaging directions landed first, 133 findings down to every Low, each fix carrying a behavioural regression test verified to fail against the pre-fix source (300+ new tests); the architecture, security, typing, test-quality, documentation and performance directions land alongside them in the same wave. Behavioural highlights, all user-visible: `upsert` no longer emits a WHERE-less UPDATE; the disk cache stopped evicting its most-recently-used entry and no longer leaks temp payloads on a failed write; polars constancy checks use exact comparison instead of a 1e-5 tolerance, so near-constant float columns are no longer silently dropped; the psycopg2 connection pool honours the requested DSN instead of the first one it ever saw; OpenRouter/OpenAI per-call metadata (`last_call_summary` and friends) is no longer shared across concurrent calls; streaming usage is recorded once per response rather than per chunk; sliding-window similarity covers the final window instead of truncating it.
- Second full-repo audit pass (58 findings across concurrency/async safety, resource lifecycle, caching, numerical correctness, config/cross-platform, logging, algorithmic complexity, and backward-compat risk — see `audits/2026-07-21_audit-round2/`) implemented in full: LLM-provider per-call state race (contextvars-backed `PerCallAttr`), unbounded provider/settings/catalogue caches now TTL/LRU-bounded, kernel-tuning cache-version/GC/remote-failure-logging fixes, `share_dataframe` int64 precision loss, several silent-fallback and lock-discipline bugs across `web`/`database`/`system`, and an unbounded-cubic-time morpheme tokenizer given a length cap.
